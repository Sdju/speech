
## Статус

**`stale` относительно `macroblocks.md` / `narrative.md`.**

Текущие `parts/0_intro.md` … `parts/9_outro.md` отражают **старый** порядок (обещания → biz/tech → критика MFE → static/dynamic → абстрактная лестница → compare).

После ок нового каркаса нужна **перенарезка** (не косметический патч).

Сохранять при миграции:

- Реализованные intro-слайды (тема, спикер, дисклеймер) — MB0 почти ок.
- Комментарии про обещания / плоскости — перенести в новые MB1–MB2.
- Куски про modules / monorepo / packages — вложить в главы Ябе, не как сухие «сценарий N».

## Стиль комментариев

- `Контент` = макет слайда; для Ябе — продукт + дерево/схема + (тихо) UI.
- `Спикер` = живая речь; каламбур только в своей главе.
- В `Контент` — `[[TODO(USER: ...)]]` где нужна личная фактура.
- `Статус: реализация` — только точечно; не материализовать соседние wireframe.

## Риски последовательности (новые)

- История 17 мин без раннего «зачем мы здесь» — держать MB1.
- Не проговорить ось static/dynamic до конца Travel — риск, что зал не отличит пакеты от MFE; закрыть в MB5a сразу после поворота (или одной фразой на 3.4).
- Каламбур Еды не должен съесть архитектурный тезис главы.
- Поворот не должен звучать как «вы всё сделали зря».
