## Стиль комментариев (после правок спикера)

- `Контент` = текстовый макет слайда, не пересказ речи.
- `Спикер` = живая речь к залу.
- Тон intro: не anti-MFE; дисклеймер «MFE != плохо», дальше проблемы и альтернативы.
- В `Контент` можно `[[TODO(USER: ...)]]` на фактуру, которую допишет спикер.

## Риски последовательности

- Обещания (MB1) → плоскости (MB2) → MS≠ (MB3a) — ок, MS≠ иллюстрирует рамку.
- Жёсткий контракт «MFE = dynamic» в MB4; в обзоре техпроблем уже мост «говорим про runtime composition / MF».
- Три техпроблемы после обзора могут съесть время — держать как optional cut.
- Лестница 2+2+2 может ощущаться шаблонно — ок для wireframe; в markdown/design разнообразим.
- Слайды «когда dynamic ок» + антипаттерн в MB8 — не вырезать ради темпа раньше optional tech.
