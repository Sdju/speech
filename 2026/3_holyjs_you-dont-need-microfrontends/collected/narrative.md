# Narrative · сквозной сценарий «Ябе.ру»

Источник драматургии для лестницы архитектур. Не кейс SM Lab — вымышленный суперприложение-паттерн.

## Зачем сценарий в докладе

Старый каркас давал лестницу **абстрактно** (модули → монорепа → пакеты) после критики MFE.

«Ябе.ру» делает то же самое **как рост продукта**: каждый архитектурный шаг — рациональный ответ на боль. Слушатель сам «доезжает» до MFE, и только тогда слышит вопрос, который старый план почти не ставил:

> Мы хорошо отвечали: **как разделить большой проект на части?**  
> Реже спрашивали: **точно ли все эти части должны оставаться одним frontend / одним проектом?**

## Два вопроса доклада (держать до конца)

| # | Вопрос | Где всплывает |
|---|--------|----------------|
| 1 | Как правильно разделить большой проект? | На каждом этапе Ябе (лестница) |
| 2 | Должны ли разделённые части оставаться одним frontend? | Финальный поворот после MFE |

Takeaway усиливается: плоскость боли + static-альтернативы + **вопрос о единстве продукта**, не только о способе распила.

## Карта этапов

| Этап | Продукт | Каламбур / тон | Архитектура | Боль, которая оправдывает шаг |
|------|---------|----------------|-------------|-------------------------------|
| Завязка | Ябе.ру (такси) | «Я беру такси» — без иронии | flat `components/pages/api` | Нечего разделять |
| 1 | + Ябе Go | «Я бегу» / «пробежаться» — первый сигнал игры | modules `taxi/go/shared` | Два сценария, разные API/экраны |
| 2 | + Ябе Еда | «Ябедам — особое место» — пауза и сразу дальше | monorepo `apps/ + packages/` | Несколько команд, shared ownership, CI всего приложения |
| 3 | + Ябе Pay | **Не дожимать шутку** — англ. Pay после русской Еды = корпоративный штрих | npm-пакеты `@yabe/*` | Разный темп релизов; общий build/deploy ещё связывает |
| 4 | + Ябе Travel | «Я беру всё» — бренд уже не про такси | MFE + shell | Почему Travel ждёт deploy Taxi? |
| Поворот | — | — | та же схема команд/деплоев | **Почему это всё ещё один frontend?** |

## Сквозной визуальный гэг (почти не комментировать)

Интерфейс Ябе на сцене эволюционирует молча; архитектура с каждым шагом «чище», продукт — менее очевиден.

```text
Старт:     [Откуда] [Куда] [Вызвать такси]
После Go:  [Такси] [Go]
После Еды: [Такси] [Go] / [Еда]
После Pay: [Такси] [Go] / [Еда] [Pay]
Travel:    Что вам нужно? · Taxi · Go · Food · Pay · Travel
```

Проговорить гэг можно один раз в финале (или оставить на наблюдательность зала). Не объяснять по дороге.

## Ритм каламбуров (жёстко)

Не выдавать пачкой. Каждый — только вместе с усложнением продукта.

1. **Ябе.ру** — нормальное имя, ноль иронии.
2. **Go** — лёгкий сигнал («пробежаться»).
3. **Еда** — панч «ябедам», пауза, сразу назад к архитектуре.
4. **Pay** — шутку не дожимать.
5. **Travel** — финальная формула «я беру всё» → мост к архитектурному повороту.

## Что сценарий несёт из старого brief (сохранить)

- Рабочее определение: MFE = **dynamic linking** (эталон MF) — назвать явно, когда доезжаем до этапа 4 / оси static↔dynamic.
- Рамка **бизнес / техника** — метод; примеры болей можно брать из этапов Ябе (вместо абстрактных TODO).
- Лестница static: модули → монорепа → пакеты; MFE = прыжок в dynamic, не «четвёртый static».
- Тон: не anti-MFE; каждый шаг рационален; вопрос в конце — не приговор.
- Без кейсов SM Lab; без туториала CI/k8s.

## Что сценарий меняет в старом каркасе

| Было | Стало |
|------|--------|
| MB5–7 — сухие «сценарии +/-» | Те же ступени = главы Ябе |
| MFE рано (MB1) → критика (MB3) → лестница «как проще» | Лестница как путь **к** MFE → поворот → цена dynamic / когда остановиться раньше |
| Один главный вопрос про инструмент | Два вопроса: как делить **и** стоит ли держать одним frontend |
| Артефакт `example/<name>/` безымянный | Кандидат имени: `yabe` / `yabe-ru` |

## Риски сценария

- **Время:** каламбуры и UI-гэг съедают воздух — +/- по ступеням вшивать в главу, не делать отдельные слайды «модульность · бизнес/техника».
- **Двойная лестница:** нельзя сначала разобрать модули/монорепу абстрактно, потом пересказать Ябе — выбрать один носитель.
- **Пародия на суперприложение:** держать вымысел; не скатываться в разнос конкретного бренда.
- **Поздний контракт «MFE = dynamic»:** до этапа Travel можно говорить «независимые куски UI / shell»; жёсткую ось static/dynamic — в момент прибытия или сразу после поворота.
- **Аналитический блок MS≠ / техпроблемы:** после эмоционального прибытия на MFE сильнее, чем до истории; optional cut по-прежнему нужен.

## Канон фраз (якоря для слайдов / речи)

- «Нам пока совершенно нечего разделять.»
- «Вот это — Такси. А вот это — Go.»
- «Кто владеет shared?» / «Почему Food ломает Taxi?» / «Почему Go ждёт CI всего приложения?»
- «Мы разделили разработку и артефакты. Пользователь всё ещё получает один большой Ябе.ру.»
- «А почему новая версия Travel должна ждать deployment Taxi?»
- «А почему всё это до сих пор один frontend?»
- «То, что мы научились удобно добавлять части в систему, ещё не отвечает, должны ли мы их туда добавлять.»
